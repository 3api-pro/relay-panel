# 请求级财务复核

管理员入口：经营管理 → 财务复核（`/admin/finance-review`）。普通操作员和观察员无法打开页面或调用 `/api/admin/finance-review`，后端在读取站点和引擎之前校验 root。

## 证据与覆盖范围

- 仅通过 Sub2API 公开管理接口 `GET /api/v1/admin/usage` 读取。New API 暂不支持，返回明确错误。
- 每次扫描一页，100 条上限；日期为 Asia/Shanghai 闭区间，最多 31 天，不接受未来日期。可按请求 ID 精确过滤。按引擎 ID 升序读取，并请求 exact_total。页面展示本页覆盖及引擎匹配总数，不能将分页扫描称为全量对账；实时新增、删除、修订仍可能影响分页。
- 仅持久化允许的请求 ID、记录 ID、模型、时间、计费方式、用户/账户/订阅编号、用量和计费数字。不会存储原始 DTO、API 密钥、嵌套用户对象、IP、User-Agent 或凭据。
- 用户消费使用 `actual_cost`，缺失/非法值为未知；不以标准价代替。账户成本公式与引擎账户统计一致：`COALESCE(account_stats_cost,total_cost) * COALESCE(account_rate_multiplier,1)`。所有金额为 USD 消费或成本记账，非现金到账。
- 引擎用量 DTO 未提供逐笔钱包扣款成功凭证。因此扫描提供核查信号，不能证明欠费，也不自动估算历史应收或补扣余额。账户成本和历史漏计费估计不可相加称为损失。

## 核查与处置

余额计费且有用量或账户成本、消费为零时进入待复核；明确零倍率与订阅用量不触发该规则。计费类型、消费金额或用户倍率缺失时标为证据不完整。未扫描请求不会出现在列表中，没有案例不表示整个区间没有异常。

`pending / reviewing / confirmed / explained / resolved` 分别表示待复核、核查中、管理员确认异常、已有合理说明和信号已解决。人工处置必须附依据。已解决要求最近 15 分钟内读取到匹配证据且信号解除，仍不等同于系统取得钱包结算凭证。合理免费请求可以填写依据并标为已说明。

按站点 ID + 引擎记录 ID 去重，重复扫描不重复建案。证据修订会记录新快照；已说明或已解决的案例会重新进入待复核。人工操作使用版本号和数据库行锁，陈旧版本返回 409。案例、事件、审计均在同一数据库事务内提交。事件不会被覆盖；页面显示最近 100 条，更早记录保留在数据库。

重新核验使用精确请求 ID、原日期，最多读取 10 页，并比对记录 ID、请求 ID、用户编号及创建时间。接口错误、身份不符、记录不存在、缺少请求 ID 或超过页数上限均为证据不可用，保留此前证据和处置状态，不会自动清除异常。

迁移 `007_finance_review.sql` 仅新增两张表和索引，兼容旧版本，可在旧服务在线时预执行；发布前完成一致性在线备份，准备迁移后再切换服务。不得用数据库恢复覆盖发布后新增支付或复核记录。
