# relay-panel v2.2.0

## 中文

本版整理用户与管理员入口，补强支付和套餐生命周期，并加入请求级财务复核及更易理解的站点接入流程。

- **入口分组：** 用户工作区与平台管理分开，管理员功能按工作台、监控任务、经营管理、平台管理分组，适配手机导航。
- **站点接入：** 内部唯一标识自动生成；“站点名称（备注）”默认使用域名，支持中文、重名和接入后修改。
- **订阅支付：** 升级按剩余时间补差价并保留到期日；降级到当前周期结束后生效。报价冻结，到账与开通可恢复，并加强支付渠道查单验证。
- **财务口径：** 区分消费记账、成本与现金充值；披露缺失和估算覆盖，未知数据不当成零，不混加不同币种。
- **财务复核：** 管理员可扫描 Sub2API 请求记录，查看证据、去重建案、记录处置依据并重新核验。
- **文档：** 更新中英文 README，简述邮件告警促成旧版 Sub2API 结算漏洞利用排查的匿名案例；统一 P4 实现状态与验收边界。

### 升级

升级前备份数据库、配置和主密钥。本版新增 `005_payment_recovery.sql`、`006_subscription_changes.sql`、`007_finance_review.sql`，应用启动时按序迁移。

```bash
git fetch origin --tags
git checkout v2.2.0
cd deploy
docker compose up -d --build
```

预构建 bundle 含源码、前后端构建产物和迁移，不含 Node.js、依赖或站点配置。使用 Node.js 22.18+（22 LTS）或 24.11+（24 LTS），按包内 `BUNDLE-README.md` 安装生产依赖后启动。Docker 仍按既有方式从源码构建。

产生新格式支付或预约套餐变更后，不可回退到忽略这些记录的旧计费实现；使用兼容版本或前向修复，禁止以旧数据库覆盖新交易。详见 [计费与回退说明](../BILLING.md)。

### 验证与边界

- 538 项后端、适配器和前端测试通过；TypeScript/Vue 类型检查与全部 workspace 生产构建通过。
- 本版功能已使用现有管理员账号完成生产桌面/手机回验；发布元数据与文档另行整理，不等于再次完成真实支付或新租户交付验收。
- 财务复核是分页扫描与人工核验，不是全量对账或逐笔钱包结算证明；不自动补扣余额。
- 退款、组织成员权限、供应商核销等仍有后续工作。P4 七项核心能力已实现，完整交付验收见 [P4 readiness](../P4-READINESS.md)。
- Sub2API 的漏洞修复需单独升级引擎，升级面板不会自动修复引擎。

## English

v2.2.0 separates operator and administrator navigation, assigns site adoption IDs automatically, and introduces editable nicknames. It adds recoverable payment fulfillment, frozen quotes, prorated upgrades, term-end downgrades, explicit financial coverage, and administrator request-level review for Sub2API.

Back up the database, configuration and secret key before upgrading. Migrations 005–007 run on startup. Once new-format payments or scheduled plan changes exist, use a compatible rollback or a forward fix; never restore an older database over new transactions.

All 538 tests, type checks and workspace builds pass. Core P4 features are implemented; complete hosted/self-hosted delivery acceptance remains open. Refund automation, organization membership and full financial reconciliation are not claimed as complete. The anonymized README incident describes monitoring that led to an engine investigation; engine patches are deployed separately.
