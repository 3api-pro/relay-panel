# API 站点服务平台：实施规划与三轮方案审议

制定日期：2026-10-22。执行授权：完成规划后持续开发、验证并上线。

## 产品范围

自部署版在客户自己的机器安装和管理 Sub2API、New API；SaaS 接入已有站点。平台不提供服务器硬件。服务对象包括站长、平台管理员、运维、财务、客服、企业团队、上游供应商、下游代理和集成商。一个人可以兼任多个角色，权限仍按组织、站点和资源授予。

## 第一轮：完整性与交付范围

- 产品观点：仅有质量图表不够，应覆盖发现异常、查请求、建事件、协作处理、复核、向客户说明的完整流程。
- 经营观点：渠道采购、漏损复核和代运营有直接价值；终端门户应解决配置和费用解释问题。
- 实施反方：一次接管所有实时流量、重写钱包和自动支付会放大复杂性，并与现有引擎重复。
- 决议：建设统一服务中心，以共享证据连接质量、经营、事件、合作伙伴、客户接入和运维交付；继续复用引擎的鉴权、路由、钱包和支付。所有模块提供可实际操作的流程和明确数据边界。

## 第二轮：被动观测与指标真实性

- 用户主张：复用真实请求、已有日志、余额和配置快照，避免用心跳调用模型造成成本。
- 运维反方：无请求时不能判断渠道可用；成功日志可能不包含失败，采集失败也不同于渠道失败。
- 数据反方：分页变化、日志清理、缺失字段、不同币种、成功与错误重复记录会使统计失真。
- 决议：默认不发送合成推理请求，不进行渠道心跳。管理 API 的有界只读日志检索与缓存复用属于采集，仍有少量网络/数据库开销。展示观测时间、采集状态、样本量、来源范围、字段覆盖；无流量显示无近期证据。消费日志不得推出全量成功率；不同事件/请求口径不混合。宿主机存活检查与渠道调用质量分开。

## 第三轮：权限、成熟度与发布

- 完整性观点：伙伴协作、事故处理、运行手册、客户说明都应有持久化记录、状态与历史，不能仅作静态入口。
- 安全反方：外部伙伴不能通过邀请自动获得全站管理员权限；公开内容不得泄露内部请求、账号、密钥或服务器。
- 验收反方：代码和单元测试不能代替 Docker 实机恢复、真实支付、邮件投递；版本回退不代表数据库迁移可逆。
- 决议：合作记录先在所属客户工作区内管理，外部访问必须有单独的有限授权契约；记录证据、状态变化与审计。新功能通过隔离数据库、现有管理员浏览器和线上只读检查验收后上线。Docker、真实支付/邮件、个人 MFA 继续按现有 P4 条件记录，不能标为通过。

## 交付顺序与验收矩阵

| 批次 | 交付内容 | 必须满足的验收 |
|---|---|---|
| A 共享证据与被动质量 | 脱敏请求采集、去重、可续采分页、数据覆盖、渠道/模型统计、费用异常线索、请求检索、导出 | 不调用推理或渠道测试；空数据/采集失败不显示正常；重复页不重复计费；越权不可读写 |
| B 事件与客服协作 | 从请求建立事件、时间线、处理/恢复/关闭、工单关联、脱敏诊断导出 | 来源同站点且可访问；版本冲突拒绝覆盖；历史保留；未验证不标自动恢复 |
| C 合作与经营 | 上游/代理/代运营档案、站点关联、报价有效期、结算事项及凭证、角色工作清单 | 区分报价/估算/实际回执，不自动划款；伙伴无隐式管理员权限；客户隔离 |
| D 客户接入与服务说明 | 客户端配置生成、模型能力说明、维护与状态公告、交付文档 | 不采集客户密钥；复制内容明确替换占位符；公开发布由站长明确选择并预览 |
| E 环境与运维交付 | 环境检查入口、版本记录、维护/升级/恢复运行手册、检查项与交付证据 | 面板备份与引擎备份区分；完成必须有依据；真实执行失败/未验证不能被自动标通过 |
| F 发布与运营 | 文档、迁移、测试、构建、旧版数据恢复验证、管理员桌面/手机验收、生产发布 | 无 demo 验收账号；已存在数据保留；生产健康检查；发布记录与未验收项明确 |

## 工作方式

各批次尽量共享同一站点、请求和事件标识，统一展示数据新鲜度。限制扫描页数、单页大小、时间范围与保留期；断线后可继续。先实现有证据的能力，缺失能力明确显示，不使用零值代替未知。高风险引擎操作复用现有权限和审计。

## 后续扩展与外部前提

实时强制预算/路由需要引擎执行能力；外部供应商与代理自助登录需要更细的资源授权；企业 SSO、自动佣金划款、多级分销不是本轮默认承诺。用户暂无 Docker 测试资源，实机安装升级恢复仍待环境。新增服务器、资金流转和额外第三方费用不由本规划自行触发。

## 本轮验收与明确保留

四个运行中的 Sub2API 站点验证了真实管理日志读取；两条历史安装失败记录不参与后台采集。New API 读取器通过上游字段契约和自动化测试，当前没有运行中的 New API 测试站点，实机验证待有环境后补充。Docker 实机安装升级恢复、真实支付/邮件和个人 MFA 沿用 P4 待验收条件。

外部伙伴自助账号、企业预算强制执行、细分财务/客服权限、供应商自动结算、知识库管理、细粒度模型兼容性认证及托管恢复执行属于后续扩展；本轮交付的是内部协作与证据工作流程，未将这些扩展标为完成。

v2.5.0 继续实现外部伙伴与岗位协作：使用已有账号、已验证邮箱和限时邀请，按供应商、代理、运维、客服、财务身份及单条事项授权。共享内容独立于内部证据，支持回复、提交结果、站点方复核和撤销。该权限范围不包含既有财务中心的细分授权、企业预算强制执行或自动结算；其余扩展和真实环境验收仍保留。


v2.6.0 继续实现客户知识库管理和人工模型能力记录：草稿与公开版本隔离、逐篇预览发布、历史恢复、整站停用、分页搜索和细分能力验证依据。管理界面与实际 PostgreSQL 并发、旧备份迁移通过验收，601 项测试通过。此处的模型说明属于站长记录，不等同于自动兼容性认证；企业预算强制执行、自动结算及既有外部环境验收仍保留。


v2.7.0 补充按站点、渠道、模型的被动预算与阈值事件，支持日/周/月周期、金额覆盖与缺口、事务去重、站长可选通知及复核记录。复用已存日志，不新增引擎读取或推理调用；这属于预算观测，实时强制预算仍需引擎能力与独立执行验收，未标为完成。

v2.8.0 继续实现日志账目的财务协作细分授权：已有财务身份需额外配置日期、渠道/模型范围，成本、明细、导出、复核分别授权；提交证据快照与站长处理留痕，权限收窄后隐藏旧版共享快照。复用已有采集结果，不扩大管理员对账权限，不触发自动结算。企业预算强制执行、客服细分工单权限及真实环境验收仍继续推进。

v2.9.0 继续实现平台客服的单条工单授权，阅读、回复、结单和内部备注分别控制；客户对话与内部备注隔离，客服不继承站点或财务范围。列表、消息及内部协作历史均可分页，撤销与回复经事务串行检查。这与站点事项协作分别授权，真实邮件投递、生产切换及其他外部验收仍保留。


v2.10.0 继续完成预算页到 Sub2API 用户平台限额的操作闭环：预览绑定、持久化意图、配置冲突检查、执行后回读、并发阻止和不确定结果复核。严格区分自然周期预算观测与引擎余额计费限额；订阅、简易模式、全企业共享池及零超额不作保证。NewAPI 限额、实际引擎拦截验收与企业总体强制预算仍保留。无新增定时心跳、模型探测或自动资金操作；真实 Docker、支付、邮件、个人 MFA 和生产切换验收继续保留。
