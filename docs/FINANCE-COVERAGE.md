# 财务汇总口径与数据覆盖

消费记账是引擎记录的对客计费金额，不是现金到账，也不是历史漏收的自动认定。上游账户成本是引擎账面成本，尚需与供应商账单核销；设置成本率后使用比例估算，页面明确标注。

区间合计、每日明细和邮件报告共用成本判定。失败站点不进入合计；未知成本保留为空，不当成零。毛利及毛利率仅覆盖消费和成本均已知的站点，毛利率分母是这些站点的消费额。API 的 `totals.coverage` 与每日 `coverage` 返回可见站点、数据可用、成本已知及比例估算数量；每日全不可用时金额与请求数为 null。区间总额保留数字类型供旧调用方兼容，无可用站点时必须通过 coverage 判断未知状态。

充值按实际支付币种分列，`rechargeCoverage` 披露成功获取站点数量。充值日期沿用引擎原始日历：目前接口没有可靠的时区标识，不能宣称是北京时间现金流水。当前适配器最多查询截至今天的 366 天窗口；超出范围返回未知，不能显示为零。消费日历查询使用北京时间闭区间，New API 按 00:00:00 至 23:59:59 转换为时间戳。

Sub2API 缺失 actual_cost 时的标价回退不可混入消费记账。不同记账单位拒绝直接合计，不作隐含 1:1 汇率转换。日期切换时前端丢弃过期响应；曲线遇到未知日期保留断点。

本次修正不建立请求级事故闭环，不执行历史补扣或退款。模型、客户、渠道下钻仍需单独完善完整性标识与请求级复核；充值时区核验、供应商核销和历史价格证据仍是后续验收项。
